# Support Matrix

This is the operational support matrix for OpenAPI 3.1.x and 3.2.x. Both versions use JSON Schema
2020-12 and share one frontend; their complete document structures are validated against vendored,
date-pinned official OpenAPI schemas before lowering. OpenAPI 3.2 is a focused extension of 3.1;
the exact delta and spargen disposition are summarized in [OpenAPI 3.2 scope](openapi-3.2.md).
Unsupported constructs fail loudly — a diagnostic and no output — rather than degrading silently
to `serde_json::Value`. Where a construct maps to an untyped value, the input schema itself was
untyped; degradation is never silent.

What a test holds here is narrower than the table may suggest: every diagnostic code a cell cites
must be a declared code, and every declared code must appear in the column its severity names
(Warned or Rejected), whatever other cells also mention it. Apart from the one exception below (the clauses of
`E023`'s row that name workspace inheritance), the prose of a cell is reviewed by hand and checked
by nothing, so an edit to it
needs the same scrutiny as the behavior it describes. Where a test pins the text `spargen explain`
prints for a code byte for byte (as for `E023`), the row defers to that text rather than restating
it; `E023`'s row quotes a few of its clauses, and a test holds each clause there that names
workspace inheritance to being a verbatim excerpt of it. Each cell names its constructs and their
diagnostic codes in a sentence apiece and leaves the list of cases reaching a code to
`spargen explain <code>`, the one copy of that list: for `E004`, `E007`, `E013`, `E016`, and
`W011` a test ties every case the body enumerates to the emission sites that report it.

| Area | Supported | Warned | Rejected |
| --- | --- | --- | --- |
| Version | OpenAPI `3.1.x` and `3.2.x`; version-specific required fields are enforced by the corresponding official schema | - | OpenAPI `3.0.x`/`<3.1`/`3.3+`/other or malformed versions (`E001`) |
| Dialect | The shared OAS base dialect (`https://spec.openapis.org/oas/3.1/dialect/base`) or omitted; OpenAPI 3.2 intentionally retains this URI, and on a 3.2 document also accepts `https://spec.openapis.org/oas/3.2/dialect/2025-09-17`, which 3.2's published document schema gives as the field's default | - | Other `jsonSchemaDialect` values, including the nonexistent `…/oas/3.2/dialect/base`, and the 3.2 URI on a 3.1 document (`E002`) |
| References | Local component refs and relative-file refs, including across files. Remote (`http`/`https`) refs, resolved **hermetically** from a locally vendored, hash-pinned copy: the opt-in `spargen lock <spec>` is the only step that fetches, writing copies under `.spargen/vendor/` and pinning each in a deterministic `spargen.lock`, so `generate`/`check` never touch the network. A JSON Pointer fragment addresses the document it is written in, except that a schema's `#/components/schemas/<name>` inside a referenced sub-file reads the root's declaration where the root declares the same name (root first, file second), while a Parameter, Request Body, Response, Header or Media Type reference reads the sub-file's alone. A schema `$ref` pointing *into* a declared component (`#/components/schemas/Envelope/properties/payload`) is walked as a JSON Pointer and lowered once per resolved `file#pointer`, as a type of its own named for the pointer's last token. A `discriminator.mapping` or `defaultMapping` value names a union member by the `file#pointer` it resolves to, not by its spelling | A sub-file's own component declaration shadowed by a same-named root declaration, and a `discriminator` beside a pointer-addressed union member that no `mapping` or `defaultMapping` entry names, which no tag then selects (`W011`; `spargen explain W011` lists the cases) | A remote ref not pinned in `spargen.lock`, or an unfetchable absolute-URI scheme such as `urn:` (`E003`). A remote ref `spargen lock` could not fetch (`E025`). A vendored copy that is missing or no longer matches its pinned `sha256` (`E021`). A reference that cannot be followed to a usable target, including one inside a subschema lowering never reads, while constructs never lowered for a client, such as a webhook body, are unaffected (`E004`; `spargen explain E004` lists the cases) |
| Schema shape | Boolean schemas, objects, arrays, tuples, maps, scalar primitives, multi-type arrays, exact JSON `null` (Rust `()`), and untyped schemas. Homogeneous scalar enums of strings, integers, or booleans, a `null` member making one `Option<Enum>`. Recursive `$ref` cycles, self- and mutually-recursive and across files, with the cycle-closing reference boxed, so a nullable alias `{oneOf: [{$ref: A}, {type: 'null'}]}` to an `A` whose `type` excludes `null` is `Option<Box<A>>`, as the direct `{$ref: A}` spelling is, while to an untyped object or array `A`, or one whose `type` lists `null`, which `null` then matches as well, it is `Box<A>`, as the same union is a non-optional `A` outside the cycle. A `$ref`'s shape-bearing siblings and an `allOf`'s members, intersected into one type — object members flattened into a single struct, scalar members narrowed — and met with a `oneOf`/`anyOf` beside them branch by branch (`spargen explain E013` states the rules). `oneOf`/`anyOf` unions, lowered to typed Rust enums with custom `Deserialize`/`Serialize` that dispatch by discriminator tag, JSON category, or typed trial matching, never `serde(untagged)` and never an untyped fallback (`spargen explain E007` states the rules), with 3.2 `discriminator.defaultMapping` generating the fallback variant. `patternProperties` as a typed overflow map when every value schema lowers to one type. `readOnly`/`writeOnly`/`deprecated`/`title`/`description` as rustdoc or `#[deprecated]`, and a representable scalar `default` on an optional field as a serde default. An optional property that is not nullable is an `Option<T>` decoded strictly, so a `null` the schema does not admit is a decode error, while on a nullable one `null` and absence are both `None`. A `required` name no `properties` entry declares is a required field typed by the object's `additionalProperties` schema | Validation-only keywords and their nested schemas, including a `patternProperties` key regex, and a union whose branches the generated type cannot tell apart, so which one a value matches is not enforced (`W001`). A `default` with no field to carry it, or one an intersection narrows away (`W005`). A `discriminator` that selects nothing — on a schema with no `oneOf`/`anyOf` of its own (the `allOf` polymorphism form is not generated), or beside a member no tag names — and a union branch or untyped keyword the enclosing schema leaves with no effect (`W011`). `spargen explain` on each code lists its cases | `patternProperties` that cannot be one typed map (`E005`). `$dynamicRef`/`$dynamicAnchor` (`E006`). A union that cannot become one generated enum (`E007`). An enum or `const` that is not a homogeneous scalar set (`E008`). An intersection — `allOf` members, or a `$ref` and its siblings — that is empty or unrepresentable (`E013`). `items` beside `prefixItems`, a tuple with a typed variable-length rest (`E015`). Static `$id`/`$anchor` scopes (`E004`). A `$ref` chain deeper than the resolver's cap (`E014`), which bounds depth only: each reference target is lowered once per resolved `file#pointer`, so recursion terminates against that reservation and never reaches it. `spargen explain` on each code lists its cases |
| Media | JSON (`application/json` and structured `application/*+json`). XML (`application/xml`/`text/xml`) request bodies and single-body responses through the `quick-xml` codec, embedded only for an API with an XML body, honoring `xml.name`, `xml.attribute`, and 3.2 `xml.nodeType: attribute` on a schema used exclusively as an XML body. Raw UTF-8 `text/*` and GitHub's `application/octocat-stream` with a string-like or binary schema. `application/octet-stream` and the concrete `image`/`audio`/`video` types as `bytes::Bytes` with a binary schema, an empty Schema Object, or none. Media **ranges** as `content` keys: a family range (`text/*`, `video/*`, `*/*`, …) ranks below every concrete codec, while the structured-suffix ranges `application/*+json` and `application/*+json-seq` are read through their suffix's codec and rank level with it (`spargen explain E009` and `spargen explain W014` state the ranking). `application/x-www-form-urlencoded` and `multipart/form-data` object requests, with **Encoding Objects** under the specification's mode switch: an explicit `style`/`explode`/`allowReserved` selects RFC 6570 serialization, otherwise the property is rendered by its `contentType`. Reusable 3.2 `components.mediaTypes`. `text/event-stream`, JSON Lines/NDJSON, and RFC 7464 JSON Text Sequences with `itemSchema` as a typed `EventStream<T>` when the stream is the operation's single bodied success response, a 3.2 SSE envelope's JSON `data` `contentSchema` being `T` | `contentMediaType`/`contentSchema` outside the SSE `data` position (`W001`). `itemSchema` on non-sequential media (`W010`). The media types a body or response offers beside the one it generates (`W014`). Encoding Object fields that cannot take effect where they are written (`W011`). An XML hint that is not applied, on a schema not used exclusively as an XML body or a type never serialized as XML (`W006`). `spargen explain` on each code lists its cases | A media type or media range spargen cannot generate for the position it is written in, a body whose schema its codec cannot carry, and an Encoding Object or XML hint spargen cannot serialize faithfully (`E009`; `spargen explain E009` lists the cases). `xml.attribute` or `xml.wrapped` beside `xml.nodeType`, which OpenAPI 3.2 forbids (`E011`) |
| Parameters | **Every RFC 6570 style the specification defines**: `simple`, `matrix`, and `label` in path; `form`, `spaceDelimited`, `pipeDelimited`, and `deepObject` in query; `form` and 3.2 `cookie` in cookie; `simple` in header — each with scalar/array/object serialization and `explode` defaults/overrides. `allowReserved: true` sends reserved characters unencoded; everywhere else delimiters are emitted literally and every data byte is percent-encoded, so a joining `,` stays distinguishable from a `,` inside a value. Path values are encoded, so no value can change the route it is spliced into. JSON content params; one 3.2 `in: querystring` parameter encoded as JSON or `application/x-www-form-urlencoded`; a parameter `default` is documented in rustdoc (never serde-wired) | examples are documentation-only; an `in: header` parameter named `Accept`, `Content-Type`, or `Authorization`, which the specification says SHALL be ignored, `allowReserved` on a parameter that is never encoded — `in: header`, or `style: cookie` — and the deprecated `allowEmptyValue` are acknowledged as having no effect (`W011`) | a style not permitted for the parameter's location; `spaceDelimited`/`pipeDelimited` with `explode: true`, which the specification's own table leaves undefined; nested arrays or objects inside a `simple`/`form` value; an object property no schema constrains, such as a `required` name no `properties` entry declares on an object with no `additionalProperties` schema, including on an object member of a `oneOf`/`anyOf` parameter schema; an uninhabited schema (`false`, or an `allOf` whose members conflict) as the parameter's own, a property's, or an item's schema, or as a `oneOf`/`anyOf` member of one, which names the union and calls only its member uninhabited — a property's or item's schema of an object, array, or tuple member of a `oneOf`/`anyOf` parameter schema counts as the parameter's own and is named the same way (`f.a`); a `querystring` parameter without exactly one JSON or form-urlencoded content entry with a schema, or with a non-object form-urlencoded schema (`E010`); duplicate parameter identities, path-template mismatches, duplicate whole-query-string parameters, mixing `query` and `querystring`, or a style/location pairing the official schema forbids (`E011`) |
| Responses | A single success body typed, and a bodyless one as `()`. The success side is exactly the 2xx statuses, so every other documented status — `304` included — is on the error side, and `default` types the success side only where no 2xx status is declared. Several documented bodies on one side, or one body beside a documented bodyless status there, become a per-operation `{Method}Response` or `{Method}Error` enum with a variant per documented status, dispatched exact before range before `default`; a streaming success body stays `EventStream<T>`. A status nothing documents is `UnexpectedStatus`, with status, headers, and body preserved, and an operation with no documented error body has an uninhabited error type. Every error shape implements `ApiErrorProblem`, and one whose bodied statuses share a body type also `ApiErrorBody`, so `Error::problem()` and `Error::api_body()` are generic over operations. The opt-in **`open_narrowing`** (`Spec::open_narrowing`, `open_narrowing = true` in `spargen.toml`, `--open-narrowing`) lowers a string `enum`/`const` narrowing a plain `string` property in a response body's own schema to an open enum with an `Other(String)` catch-all (the book's runtime chapter, under problem details, states which positions stay closed). **Documented response headers** become a per-(operation, status) struct read by `from_headers`/`from_response` as an explicit second step, with a documented `Set-Cookie` a list of its values, never comma-joined. 3.2 response `summary`/optional `description` become rustdoc | A response header with no typed accessor: a `Content-Type` header, which the specification says SHALL be ignored, or one whose `schema` or `content` spargen cannot read as a single value (`W011`) | a Responses key that is neither `default`, a specification extension (`x-`), a three-digit status code, nor one of the ranges `1XX`–`5XX` — the official schema's own rule, applied to a Responses object in any file of the bundle (`E011`) |
| Security | `http` bearer/basic and `apiKey` (header/query/cookie) attach registered credentials per operation `security` (first satisfiable alternative; a missing credential is a typed request-construction error, `RequestError::MissingCredential`, naming each alternative's unregistered schemes, a credential of a kind its scheme cannot carry is `RequestError::CredentialMismatch`, naming the scheme, the kind it carries, and the `Credential` variant registered, and a failed token provider is `RequestError::CredentialProvider`, all three raised before anything is sent); `oauth2`/`openIdConnect`, including 3.2 metadata/device-flow descriptions, accept a caller-supplied token attached as bearer; a `$ref`-valued security scheme is resolved, one level deep, to a scheme the same document declares; scheme documentation (`bearerFormat`, flows, `openIdConnectUrl`, deprecation) becomes rustdoc on credential registration; a 3.2 Security Requirement URI resolves with component-name precedence | `mutualTLS` is always satisfiable and attaches nothing — the transport's client certificate satisfies it (`W011`) | a requirement naming an undeclared scheme, or an `http` scheme other than `bearer`/`basic`, reported where it is declared rather than only where it is used (`E012`); a `$ref`-valued security scheme that cannot be followed in one hop to a scheme declared under the same document's `#/components/securitySchemes/` — one whose target is itself a `$ref` (chained aliases, including an alias to itself, are not followed), is not declared, or lies outside that map, such as a file-relative reference — each reported with its own message at the aliasing scheme (`E004`) |
| Document | Servers lowered **with their variables** into a typed builder per templated server (an `enum` variable becomes a Rust enum) plus `Client::with_default_server`, and path-item and operation `servers` overrides sent per call with each variable at its default. Path Item `$ref`, one level deep and across files, its `summary`/`description` overriding the referenced item's. 3.2 `$self` as the canonical root identity for reference resolution. `QUERY` and every valid `additionalOperations` method as client methods. Info, path-item, operation, response, and tag metadata as rustdoc, with Server `name` also naming the generated builder type (`servers::{Name}`), so renaming it is a breaking change. `requestBody.required` choosing `&T` or `Option<&T>` in the generated signature | `webhooks`, operation `callbacks`, and response `links`, acknowledged with no code emitted (`W002`). A Reference Object's `summary`/`description`, a server variable its `url` never uses, and a `servers` entry past the first on a path item or operation (`W011`) | Malformed JSON/YAML, a structure the version's official OpenAPI schema rejects in the root document or any file a `$ref` reaches, and the semantic rules that schema cannot express, such as a duplicate `operationId` (`E011`; `spargen explain E011` lists them). An object or mapping that declares the same key twice (`E022`). A Path Item `$ref` beside structural siblings, which the specification leaves *undefined* (`E016`). A Path Item `$ref` whose target is itself a Path Item `$ref` (`E004`) |
| Build cache | Build-time generation fingerprints the generator, complete transitive local/vendored input set, lock file, and config under Cargo's `OUT_DIR`; missing, stale, or manually edited output is regenerated | - | - |
| Runtime dependencies | After lowering, build-script and proc-macro generation derive the crates/features referenced by that API and audit the consumer manifest before emitting code; `spargen deps <spec>` prints that exact `[dependencies]` block up front, each crate at its tested floor with the features the API uses, from the same table the audit reads, and is the one place those floors are listed. The blocking client's native optional `tokio`, required only when the consumer declares `blocking`, may be placed in any native-only `[target.…]` table: under a build script the tables are evaluated for the target being built, as Cargo does, and a wasm32 build needs none; from `generate_api!`, which cannot see the target, they must jointly cover every non-wasm target. Higher compatible caret floors are allowed; unrelated dependencies and features are ignored. A dependency declared `workspace = true` is followed to the workspace root's `[workspace.dependencies]`; a member's `default-features = false` cannot turn off defaults the root leaves on, so disable them in `[workspace.dependencies]`. Inheriting a required crate therefore satisfies the audit. Those clauses are quoted verbatim from the text `spargen explain E023` prints, whose wording a test pins byte for byte, and a second test holds every clause of this row that names workspace inheritance to being such a quotation, so how the root is found, how version, features and `optional` combine, and what the diagnostic reports when no root is found or one cannot be read are stated there and only there. Cargo resolves the accepted declaration and rustc proves the selected versions compile the emitted API | Generation outside a build script cannot emit rebuild triggers or find a manifest to audit, and says so (`W013`, or `W012` when only the manifest is missing) unless the caller declares `CargoIntegration::Off` | Cargo integration declared `Required` but unavailable (`E024`); a missing dependency/feature, a requirement admitting a version below the tested floor or crossing the next breaking line, reqwest defaults enabled, a renamed runtime crate, invalid `blocking` wiring, or no native-only `tokio` table applying to the build target (or, from a proc-macro, covering every non-wasm target) (`E023`) |
| Compatibility | exact and glob (`*`, `**`, `?`) omit rules for paths, operations, components, pointers, file-local pointers; auto-carve of rejected constructs | matched omissions, one per removed construct (`W009`) | an exact or glob omit rule that matches nothing, a pointer rule naming the document root or an unloaded file (`E019`), invalid post-omit document (`E020`) |
| Targets | native targets (async client, plus the opt-in `blocking` client) and **`wasm32-unknown-unknown`** — the browser, via reqwest's `fetch` backend. The embedded runtime carries conditional `Send`/`Sync` bounds (`MaybeSend`/`MaybeSync`), so the transport seam, middleware/retry helpers, auth token providers, and streaming compile against reqwest's `!Send` wasm futures; consumers target-gate `tokio` native-only in their own manifest | on wasm the `blocking` client is unavailable (its tokio runtime cannot run on the single-threaded browser — the `BlockingClient` is `cfg`-gated off wasm) and streaming (`EventStream`) delivers non-incrementally, buffering the whole body once via `fetch` (the browser buffers it regardless; the API and items are identical). `error_body_cap` bounds only retention on wasm, never reading, because `fetch` exposes no incremental read; the emitted `ClientConfig::max_error_body` doc ([source](https://github.com/getkono/spargen/blob/master/support-runtime/src/client.rs)) states where the cap applies on each target and the two paths it does not cap. Native-only reqwest features configured on the injected client (timeouts, TLS backend, proxies) are browser/`fetch` limitations, not spargen ones | - |

Generated output is freestanding Rust with embedded support code and no `spargen` runtime
dependency. It compiles for native targets and `wasm32-unknown-unknown` (browser `fetch`); see the
**Targets** row for wasm limitations (no blocking client, non-incremental streaming, and an
error-body cap that bounds retention but not peak).
